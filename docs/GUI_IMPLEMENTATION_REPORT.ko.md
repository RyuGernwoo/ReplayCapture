# GUI 개선 구현·검증 보고서

- 대상: ReplayCapture 0.1.0 GUI 개선 작업
- 작성일: 2026-09-10
- 기준 설계: [GUI 디자인 개선 계획](GUI_DESIGN_IMPROVEMENT_PLAN.ko.md)
- 사용자 평가: 사용자 요청에 따라 생략
- 검증 원칙: 실행 결과와 미검증 항목을 분리하며, 짧은 성능 시험을 장시간 안정성 보장으로 해석하지 않는다.

![개선된 녹화 화면](images/gui-dashboard.png)

설정 화면은 기본 항목을 그룹으로 나누고 고급 항목을 접어 두었다.

| 저장 | 주요 버튼 강조, 잘못된 길이·전체 길이 대기·부분 저장 안내 |
| 바로가기 | 대시보드에서 단축키 변경과 적용된 저장 폴더 열기 |
| 설정 | 화면과 소리·기록과 저장·일반 그룹, 고급 화질·자원 접기 |
| 편집 | 미적용 상태 안내, 화면 이동 시 편집 값 유지, 적용값으로 되돌리기 |
| 검증 | 숫자 범위·짝수·시간 관계·메모리 관계·경로 오류를 입력칸 근처에 표시 |
| 단축키 | 등록·충돌 복구·편집 중 저장 억제 유지, 테스트 종료 문구 |
| 작업 | 결과 상태, 선택 작업 상세, 상태에 따른 열기·취소 활성화 |
| 도움말 | 사용자 문제 해결 안내와 기술 진단을 함께 제공 |

설정과 녹화 엔진의 저장 계약은 유지했다. 일시정지·중지·버퍼 비우기가 미저장 기록을 제거한다는 사실을 화면에 표시한다. 최근 기록 저장은 GUI·전역 단축키·트레이에서 제공한다.

## 설계 조정

- 단축키의 발견 가능성과 기존 직접 진입 경로를 유지하기 위해 독립 메뉴를 유지했다. 계획의 네 개 탐색 항목 대신 다섯 개를 사용한다.
- 접근 가능한 네이티브 입력·목록·버튼을 유지하고 주요 행동에만 사용자 지정 색상을 적용했다.
- 프레임워크를 전환하지 않았다. 색과 상태 변환은 별도 헤더로 분리하고 배치는 기존 App 안의 행 기반 구조로 정리했다.
- 고급 설정은 접을 수 있지만 설정 그룹 내부는 스크롤로 탐색한다. 모든 기존 기능에 GUI 경로가 있다.
- 화면 이동 시 편집 값을 보존하는 방식으로 미적용 값을 처리한다.
- 실시간 미리보기, 다크 테마, 영구 파일 라이브러리, 가짜 내보내기 백분율은 추가하지 않았다.

## 기능 및 배치 검증

- Release 빌드 및 단위 테스트: 통과.
- 실제 GUI: 녹화 시작·저장·일시정지·재개·중지 통과.
- 설정 적용과 재실행 후 복원: 통과.
- 사용자 지정 전역 단축키·숨긴 창에서 저장·충돌 롤백·테스트 모드: 통과.
- 고급 설정 접기·펼치기, 잘못된 폭 입력의 인라인 오류, 변경 되돌리기, 화면 이동 중 편집 값 유지: 통과.
- 잘못된 이번 저장 길이에 대한 버튼 비활성과 이유 표시: 통과.
- 96·120·144·168·192 DPI 메시지를 이용한 가로 배치 계산: 통과.
- 짧은 창에서 대화상자 방식 키보드 포커스 순회 및 적용·종료 버튼 도달: 통과.
- 글자 대비 계산: 본문/배경 15.16:1, 주요 버튼 글자/배경 6.16:1.

DPI 메시지 주입은 배치 계산 시험이다. 실제 여러 모니터를 이동한 검증이나 운영체제 전체 배율 변경 시험과 같지 않다. 키보드 포커스 검증도 외부 사용자 평가 또는 Narrator 검증을 대체하지 않는다.

## 성능 측정

각 버전을 90초씩 실행한 최종 비교다. 성능 개선을 주장하기 위한 반복 통계 실험은 아니다.

| 지표 | 기존 버전 | 개선 GUI |
|---|---:|---:|
| 평균 CPU (전체 8개 논리 프로세서 기준) | 1.89% | 2.28% |
| 평균 CPU (단일 코어 기준) | 15.15% | 18.24% |
| 최대 작업 집합 | 245.79 MiB | 245.17 MiB |
| 최대 Private 메모리 | 225.60 MiB | 223.86 MiB |
| UI 메시지 왕복 p95 | 0.393 ms | 0.362 ms |
| UI 메시지 왕복 최대 | 2.207 ms | 1.686 ms |
| 입력 프레임 / 누락 | 2679 / 16 | 2707 / 8 |
| GDI 객체 (첫 샘플 → 마지막) | 57 → 46 | 63 → 45 |
| USER 객체 (첫 샘플 → 마지막) | 102 → 96 | 139 → 132 |
| 핸들 (첫 샘플 → 마지막) | 530 → 591 | 530 → 590 |
| 최근 10초 저장 | 3개 완료 | 3개 완료 |

이번 측정에서는 평균 CPU가 약 0.39%p 증가했고 작업 집합 최대치는 비슷했다. UI 객체 수는 증가한 화면 컨트롤을 반영하며, 첫·마지막 샘플만으로 누수 유무를 확정하지 않는다. 핸들은 초기 연결 전후 조건이 달라 양쪽 모두 증가했다. 측정 중에는 녹화와 저장이 완료되었으며 UI 메시지 왕복에서 3ms를 넘는 응답은 관찰되지 않았다.

원본: `artifacts/gui-baseline-final/performance.json`, `artifacts/gui-after-final/performance.json`. 비교용 기존 실행 파일은 변경 전 빌드에서 별도로 복사했다. 측정 뒤에는 확보 시간 표기를 보관 한도로 제한하고 선택 모니터를 표시하는 보정만 추가했으며, 캡처·내보내기 코드는 바꾸지 않았다.

측정 도구는 1초 간격으로 프로세스 CPU·작업 집합·Private 메모리·핸들·GDI/USER 객체 수를 기록한다. 일정 간격으로 탐색과 크기 변경을 수행하고, 종료 15초 전에 최근 10초 저장을 세 번 요청한다.

UI 응답 시간은 WM_NULL 메시지 왕복 시간이다. 파일 저장 완료 지연이나 실제 화면 표시 지연을 의미하지 않는다. CPU 전체 비율은 단일 코어 기준 비율을 논리 프로세서 수로 나눈 값이다.

## 실제 영상·오디오 검증

75초 수집 시험에서 최근 60초 저장을 동시에 세 번 요청했다. 모든 파일의 H.264 영상과 AAC 오디오를 PyAV 18.1.0으로 끝까지 디코딩했다.

| 항목 | 결과 |
|---|---:|
| 완료 파일 | 3개 |
| 실제 길이 | 각 60.998초 |
| 저장 전후 입력 프레임 | 2430 → 2459 |
| 누락 프레임 | 13 |
| 디코딩 프레임 / 파일 | 영상 1830, 오디오 2860 |
| 최초 영상·오디오 시각 차이 | 4ms |
| 최종 영상·오디오 프레임 시각 차이 | 약 29.3ms |
| 최대 키프레임 간격 | 1초 |
| 오디오 최대 신호값 | 약 0.262, 무음이 아님 |

저장 중에도 입력 프레임이 증가했다. 출력이 약 1초 긴 것은 앞쪽 키프레임부터 저장하는 정책과 일치한다. 프레임 타임스탬프 차이는 외부 플래시·비프 기준의 절대 동기 측정과 구분한다.

원본: `artifacts/gui-media-final/result.json`, `artifacts/gui-media-final/decode-report.json`.

## 배포 패키지 검증

`dist/ReplayCapture-0.1.0-windows-x64.zip` 생성 후 별도 폴더에 압축을 풀어 동일 GUI 회귀 검증을 수행했다. 녹화·저장·단축키 충돌·숨긴 창 저장·설정 복원이 통과했다. README의 아이콘과 화면 이미지, 내부 문서 링크가 압축 해제 폴더에서도 존재함을 확인했다.

빌드 출력과 ZIP에서 꺼낸 실행 파일의 SHA-256이 일치한다. 패키지 검증 이후 보고서만 보완했으며 실행 파일은 변경하지 않았다. 패키지 GUI 원본 결과는 `artifacts/gui-package-validation/result.json`이다.

## 재현 명령

```powershell
./scripts/build.ps1
python tests/ui_probe.py --run-name gui-final
python tests/gui_layout_probe.py --run-name gui-layout-final
python tests/gui_performance.py --exe build/Release/ReplayCapture.exe --output artifacts/gui-performance --seconds 90
./build/Release/replay_integration.exe artifacts/gui-media 75
python tests/verify_media.py artifacts/gui-media --min-duration 59
./scripts/build.ps1 -Package
```

개발 검증용 Python에는 Pillow·psutil이 필요하며, 독립 미디어 디코딩 검증에는 PyAV·NumPy가 필요하다. 일반 사용자 실행에는 이 도구들이 필요하지 않다.

시험 원본은 Git에서 제외된 artifacts 폴더에 저장된다. 성능 측정은 동일 작업 부하를 정확히 재생하는 벤치마크가 아니라 동일 설정의 실제 데스크톱 비교다.

## 남은 한계

- 요청에 따라 사용자 평가를 수행하지 않았다.
- Narrator, 실제 고대비 모드 전환, 다양한 물리 모니터 조합은 미검증이다.
- 실제 2시간 A/V 드리프트와 8시간 내구성 시험을 수행하지 않았다.
- CPU·메모리 수치를 다른 PC, GPU, 드라이버에서의 보장값으로 해석하면 안 된다.
- 코드 서명과 별도 클린 PC 배포 검증은 이번 GUI 변경의 완료 근거에 포함하지 않는다.
