## 핵심 결과

실제 화면과 시스템 오디오를 수집한 뒤 최근 60초 저장을 동시에 세 번 요청했습니다.

| 항목 | 관찰값 |
|---|---:|
| 저장 파일 수 | 3개 |
| 각 파일 길이 | 약 60.7537초 |
| 저장 중 영상 프레임 진행 | 2273 → 2302 |
| 디코딩된 영상 프레임 | 1823 |
| 디코딩된 오디오 프레임 | 2848 |
| 첫 오디오 시작 차이 | 약 +8ms |
| 마지막 타임스탬프 차이 | 약 10.7ms |
| 관찰된 키프레임 간격 | 1.0초 |
| 오디오 신호 | 무음이 아닌 값 확인 |

요청한 60초보다 약 0.75초 긴 결과는 디코딩 가능한 앞쪽 키프레임부터 저장하는 현재 정책과 일치합니다. 내보내기 중 영상 프레임 번호가 계속 증가해 저장 작업이 캡처를 막지 않는 것도 확인했습니다.

## 사용자 흐름 검증

~~~mermaid
flowchart LR
    A[앱 실행] --> B[장치 선택]
    B --> C[녹화 시작]
    C --> D[GUI 또는 단축키 저장]
    D --> E[MP4 재생 확인]
    C --> F[일시 정지·재개]
    C --> G[트레이 숨김·복원]
    E --> H[설정 저장 후 재실행]
    H --> I[설정 복원 확인]
~~~

다음 흐름을 실제 GUI에서 확인했습니다.

- 녹화 시작 → 최근 기록 저장 → 일시 정지 → 재개 → 중지
- 설정 변경 후 캡처 재시작과 버퍼 초기화 안내
- 창이 숨겨진 상태에서 사용자 지정 전역 단축키 저장
- 이미 사용 중인 단축키 등록 실패와 기존 조합 복원
- 앱 재실행 뒤 설정 유지
- 배포 ZIP 압축 해제 뒤 실행과 Windows Media Foundation 재생

## 자동 검증 실행

~~~powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
~~~

## 아직 남은 검증 ⚠️

다음 항목은 현재 결과만으로 보장하지 않습니다.

- 2시간 이상 연속 녹화의 장기 A/V 드리프트
- 8시간 이상 내구성, 메모리 증가, 핸들 누수
- 외부 플래시·비프 기준의 절대 A/V 동기
- 저장 지연 p95와 장시간 CPU 사용률 목표
- NVIDIA·AMD·Intel의 여러 GPU와 드라이버 조합
- 모니터 분리, 오디오 장치 제거, 디스크 가득 참, 절전 복귀의 전체 실패 매트릭스
- 별도 클린 PC에서의 설치·제거 및 SmartScreen 흐름
- 공개 배포용 코드 서명

릴리스 범위를 넓히기 전에는 위 항목을 별도 하드웨어와 장시간 시험으로 보완해야 합니다.
