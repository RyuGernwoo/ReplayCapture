# ReplayCapture 0.1.0 검증 보고서

검증일: 2026-09-09~10. 아래는 실제 실행한 결과이며 초기 계획서의 모든 출시 목표를 충족했다는 의미는 아닙니다.

## 검증 환경

- Windows 11, OS 빌드 26200, x64
- Intel Arc 130V GPU (8GB), 드라이버 32.0.101.8626
- Intel Quick Sync Video H.264 Encoder MFT
- MSVC 19.44.35222, Windows SDK 10.0.26100.0
- 독립 디코더: PyAV 18.1.0 (개발 시험 전용, 제품에 포함하지 않음)

60초 통합 시험은 세 저장 작업을 동시에 허용하기 위해 총 메모리 예산 768MiB로 실행했습니다. 완료 후 압축 버퍼 데이터는 약 75.2MB였으며 누락 카운트는 8입니다. 이 수치는 실제 프로세스 전체 메모리 사용량이나 장시간 누수 측정치가 아닙니다.

오디오 첫 PTS는 영상보다 8ms 뒤, 마지막 PTS 차이는 약 10.7ms였습니다. 이는 **트랙 시간축의 정렬**을 확인한 것이며, 외부 플래시·비프를 이용한 실제 시청각 지연 측정을 대체하지 않습니다.

## 시험에서 발견하고 처리한 항목

- 초기 GUI 렌더링에서 배율에 따른 창 크기를 보정했습니다.
- 버튼 포커스 알림을 실제 클릭과 구분하도록 처리했습니다.
- 자동 GUI 시험에서 확인 대화상자의 버튼 ID를 고정해 잘못 조작하던 부분을 수정했습니다. 실제 확인 버튼을 찾고 대화상자가 닫힌 뒤 다음 조작을 수행합니다.
- 총 메모리 예산 512MiB에서 대용량 60초 저장 3개를 동시에 접수했을 때 세 번째 작업이 자원 제한으로 실패했습니다. 이는 예상된 보호 동작이며 오류가 작업 화면에 표시됩니다. 예산 768MiB에서는 3개 모두 성공했습니다.
- 접수 직후 녹화 중지·버퍼 비우기가 저장 요청을 지우지 않도록 캡처 종료 순서를 보완했습니다.

## 원시 결과와 재현

로컬 시험 산출물은 Git에서 제외되는 `artifacts/` 아래에 있습니다.

- `artifacts/acceptance-final/result.json`: 반복 저장·프레임 카운트
- `artifacts/acceptance-final/decode-report.json`: 독립 전체 디코딩 결과
- `artifacts/ui/result.json`: GUI·단축키·설정 영속화 시험
- `artifacts/ui/*.png`: 프로그램 창 렌더링 결과
- `artifacts/package-ui/result.json`: 배포 ZIP 실행 파일의 GUI 재검증
- `artifacts/package-ui/recordings/decode-report.json`: 배포 앱 저장 영상의 독립 디코딩

개발 시험 명령:

```powershell
./scripts/build.ps1 -Package
./build/Release/replay_integration.exe artifacts/integration 70
python tests/ui_probe.py
python tests/verify_media.py artifacts/integration --min-duration 60
```

실제 화면·소리를 기록하는 시험은 로그인된 데스크톱과 재생 장치가 필요합니다. GUI 시험은 별도 테스트 설정 경로를 사용합니다.

## 아직 검증하지 않은 범위

- 2시간 시청각 drift 및 8시간 실제 상주·누수 시험
- 외부 기준 플래시·비프에 의한 절대 시청각 지연
- CPU 평균 5% 및 모든 저장 요청의 p95 지연 목표
- NVIDIA·AMD 및 다른 Intel 드라이버, 소프트웨어 인코더 성능
- 실제 잠금·절전·장치 분리·디스크 가득 참의 전체 물리 환경 행렬
- 별도의 깨끗한 PC에서 실행·제거, 공개 코드 서명

따라서 현재 산출물은 **현재 PC에서 핵심 기능을 검증한 실행 가능한 초기 버전**입니다. 범용 Windows 제품의 장시간·다중 장비 출시 인증이 완료된 상태로 표기하지 않습니다.
